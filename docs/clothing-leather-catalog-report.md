# Каталог «Одежная кожа» — отчёт

## Использованные данные

- Источник: экспорт Tilda `store-11012911-202607191359.csv`, сохранённый в `data/source/`.
- В каталог импортировано 88 родительских товаров и 176 связанных вариантов (264 строк категории).
- Перенесены идентификаторы Tilda, названия, исходные URL и изображения, категории, характеристики, единицы/порции, цены и `Price Old` вариантов.
- Варианты связаны с товаром по `Parent UID` и не выводятся отдельными карточками.
- Подкатегории, найденные в данных: «Гладкая», «Винтажная», «Фактурная», «Перфорированная», «КРС».
- Для фильтра объединены «Черный» и «Чёрный»; исходный цвет в карточке и на товарной странице сохранён.

## Импорт и контроль данных

Скрипт `npm run import:clothing-leather` читает исходный CSV и генерирует `src/data/clothingLeatherProducts.ts` и `public/sitemap.xml`.

- Строк в исходном файле: 518.
- Строк одежной кожи: 264.
- Потерянных `Parent UID`: 0.
- Дублирующихся ID: 0.
- Дублирующихся URL: 0.
- Товаров без цены, изображения или цвета: 0.

Скрипт завершится ошибкой при потерянном родителе, дублирующемся ID или URL.

## Противоречия и решения

- В задании URL товара ограничен `/odejnayakozha/tproduct/`, но один реальный товар `Metallica` находится по `/odejnayakozha/gladkaya/tproduct/`. Импортёр учитывает этот единственный вложенный путь, чтобы сохранить заявленные 88 товаров.
- В CSV есть два повторяющихся legacy slug (`naturel` и `jeans-effect`). Локальный URL всегда содержит уникальный ID (`/odejnayakozha/tproduct/:id-:slug`), поэтому конфликта маршрутов нет.
- В CSV нет поля валюты. На странице показаны только исходные числовые цены и единицы измерения, без добавления валюты. `Product` schema публикуется без `Offer`: валюту для price-rich result нужно подтвердить вручную.

## Реализация

- Страница каталога: `/odejnayakozha`.
- Алиас: `/catalog/clothing-leather`.
- Страница товара: `/odejnayakozha/tproduct/:id-:slug`.
- Фильтры и сортировка сохраняются в query-параметрах URL.
- В первом рендере показано 16 карточек; остальные загружаются кнопкой «Показать ещё».

- Изображения вне первых четырёх карточек загружаются лениво; вёрстка проверена на 360 px без горизонтального скролла.

## Качество товарных изображений — v2

### Причина размытия

Предыдущая версия использовала один thumbnail с WebP quality **78** и AVIF quality **45**. Хуже того, геометрия ImageMagick ограничивала обе стороны (`680x680>`): для вертикальных фото вариант, выглядевший как 680 px, фактически получался около 340 px шириной. Этот файл использовался и для Retina-карточек, поэтому фактура кожи заметно смягчалась.

### Новый pipeline

- WebP — единственный production-формат товарных фото: quality **90**, method **6**, `webp:use-sharp-yuv=true`; без blur, denoise, цветокоррекции и апскейла.
- Новый resize ограничивает **только ширину** (`WIDTHx>`). Исходники меньше целевого варианта сохраняются в нативном разрешении, а не растягиваются.
- Варианты получают cache-busting имена `w480-v2.webp`, `w720-v2.webp`, `w960-v2.webp`, `w1280-v2.webp`, `w1440-v2.webp`, `w1920-v2.webp` — только когда исходник достаточно широк.
- Для карточек используются `480w / 720w / 960w / 1280w` плюс нативный максимум; для страницы товара — `960w / 1440w / 1920w` плюс нативный максимум.
- AVIF для товаров отключён: в прежнем сравнении при quality 45 он заметно размывал мелкое зерно. AVIF остаётся допустимым для hero, но WebP — основной формат фактуры кожи.
- Модель данных содержит `images[].card` и `images[].full`, у каждого — `src`, `srcSet`, `sizes`, реальные width/height и перечень файлов. Страница товара больше не использует card source.

Пример production `srcset`:

```html
srcset="…/w480-v2.webp 480w, …/w720-v2.webp 720w, …/w960-v2.webp 960w, …/w1280-v2.webp 1280w"
sizes="(max-width: 639px) calc(100vw - 40px), (max-width: 1023px) calc((100vw - 80px) / 2), (max-width: 1439px) calc((100vw - 400px) / 3), 252px"
```

## Цены в рублях

### Как формирует цену старый сайт

Публичные товарные страницы Tilda хранят исходные значения в CSV и в product records (например, `5` за `фут2`, `0.53` за `дм2`). В HTML всех проверенных страниц подключён `daily_jsonp.js`, функция `CBR_XML_Daily_Ru` и код OZELIF, который добавляет 10% к значению USD и записывает результат в атрибут `data-rub-price`. Витрина показывает именно этот атрибут с символом `₽`.

Это **не фиксированный коэффициент**: его значение зависит от виджета старого сайта. Поэтому `conversionRate` в `data/catalog/clothing-leather-prices.json` намеренно равен `null`, а новый сайт не делает запросов к ЦБ или валютным API. Вместо этого он использует снимок фактически отрисованных сумм старого сайта от 2026-07-19 (`conversionMethod: tilda-rendered-price`).

Скрипт `npm run import:clothing-leather-prices` проходит 88 legacy URL с паузой 120 мс, проверяет Tilda UID и наличие прежнего renderer, сопоставляет варианты по UID / External ID и создаёт cache. Он завершается ошибкой при неизвестной исходной сумме, неверном URL или неоднозначном варианте. `npm run verify:clothing-leather-prices` проверяет 88 товаров, 176 вариантов, валюту, единицы, External ID, старые цены и несовпадения.

# OZELIF → Yandex Direct MCP: защищённая сводка заказов

Экспериментальная серверная интеграция для проверки заказов, без передачи персональных данных посетителей в ChatGPT.

## API

`GET /api/internal/direct/order-evidence?campaignId=715543180&dateFrom=2026-10-01&dateTo=2026-10-14`

Требует заголовок `Authorization: Bearer <secret>`. Если `OZELIF_MCP_ORDER_READ_TOKEN` отсутствует или короче 32 символов, endpoint возвращает 404.

Ответ содержит только агрегированные количества заказов, количество заказов со статусом «оплачен» в истории CRM, сумму по этим заказам в рублях и количество записей доставки события покупки в Метрику со статусом `sent`. Телефоны, контакты, ФИО, комментарии, адреса и ID отдельных покупателей **не возвращаются**.

Внимание: фильтрация кампании по сохранённому `utm_campaign` является атрибуцией, заявленной URL-параметром, а не независимой проверкой источника клика. `paid` отражает статус CRM, а не подтверждение платежа от эквайринга. `purchaseOutboxSent` означает принятую отправку системой доставки; **это не доказательство срабатывания цели 609951402 в Метрике**. `checkoutGoalVerified` пока всегда `false` — требуется отдельная поштучная корреляция `order_id` с событием Метрики, которой ещё нет в текущем клиентском событии `order_created`.

## Включение (только после ревью PR)

1. Подготовьте отдельный случайный ключ на сервере (пример команды: `openssl rand -hex 32`). Не помещайте его в Git или в диалог ChatGPT.
2. Сохраните секрет на сервере как `OZELIF_MCP_ORDER_READ_TOKEN` в приватном окружении сервиса API, а тот же ключ — в защищённом окружении MCP-клиента. Не используйте `ADMIN_SESSION_SECRET` и не переиспользуйте токен Яндекс Директа.
3. Убедитесь, что HTTPS-путь `/api/internal/direct/order-evidence` маршрутизируется Nginx к этому API. Запрос без ключа должен вернуть 401, а при отсутствии сервера-секрета — 404.
4. На стороне MCP установите `OZELIF_REPORT_CURRENCY=RUB` **только после** проверки валюты расходов в рекламном кабинете.
5. Протестируйте период, в котором известны заявки с UTM `utm_campaign` конкретной кампании. Если UTM не содержат числовой ID кампании, метод законно вернёт ноль и потребуется отдельная корректная схема связывания.
6. Проверка с настоящим API должна быть read-only, без включения рекламных записей.

## Проверки

`node --test server/lib/marketing-order-evidence.node-test.mjs` — API и чистый агрегатор с фиктивной БД.

Не запускать клиентский скрипт отправки покупок в Метрику для этой задачи: он выполняет внешние события и не нужен для чтения.

## Необходимые дальнейшие доработки

- Поштучно сверять конкретные заказы и события цели из Logs API Метрики, без передачи клиентских персональных данных.
- Подтверждать оплату через платёжного провайдера (если бизнес требует подтверждённый ROAS, а не CRM-статус).
- Настроить мониторинг и лимиты доступности endpoint, журналировать только коды ошибок, не запросы/секреты.
